# fastcar — marketing site

A self-contained static marketing site for
[fastcar](https://github.com/Heyo-Computer/fastcar), a multi-vendor agent
harness built on the [Pi coding-agent SDK](https://pi.dev).

The site is plain HTML, CSS, and a tiny bit of JavaScript — no framework, no
bundler. "Building" is a verified copy of the source into `dist/`, and the
local preview server is a single zero-dependency Node script.

## Structure

```
site/
├── index.html        # Landing page: hero, features, how it works, CTA
├── 404.html          # Minimal 404 page
├── styles/
│   └── site.css      # Dark theme (IBM Plex Mono + Silkscreen, peach accent)
├── scripts/
│   ├── main.js       # Smooth-scroll + mobile nav toggle
│   ├── build.js      # Copy source → dist/ and verify the files are there
│   └── serve.js     # Zero-dependency static server for dist/
├── package.json      # build / serve / dev scripts
└── README.md         # This file
```

`dist/` is generated by the build and is gitignored (see `.gitignore` below).

## Prerequisites

- Node ≥ 18 (the build & serve scripts use only the Node standard library;
  the dev dependencies in `package.json` are for the convenience scripts)

## Install

```sh
cd site
npm install
```

## Build

```sh
npm run build
```

Copies the static source into `site/dist/` and verifies every expected file
landed there:

```sh
npm run build
#   ✓ index.html
#   ✓ 404.html
#   ✓ styles/site.css
#   ✓ scripts/main.js
#   ✓ package.json
#   ✓ README.md
#
#   Build complete → site/dist/
```

## Local preview

```sh
npm start        # build, then serve on http://localhost:3000
# — or —
npm run serve    # serve an existing site/dist/ on http://localhost:3000
```

The preview server serves `index.html` for `/` and falls back to `404.html`
for any unknown path, so deep links land on the 404 page instead of a bare
error. Change the port with `PORT=8080 npm run serve`.

### Watch mode (live rebuild)

```sh
npm run dev      # rebuild on file change + serve on http://localhost:3000
```

## Deploying

`dist/` is a flat directory of static files, so it deploys anywhere:

- **GitHub Pages** — point Pages at the `dist/` output (or a branch that a
  workflow publishes `site/dist/` to). If serving from a sub-path, set the
  `<base>` accordingly; the site uses relative asset paths (`styles/site.css`,
  `scripts/main.js`) so it works without a base href on a root domain.
- **Netlify / Vercel / Cloudflare Pages** — set the build command to
  `cd site && npm install && npm run build` and the publish directory to
  `site/dist`.
- **Any static host / S3 / nginx** — upload the contents of `site/dist/`.
  Configure the host to serve `404.html` on 404.
- **Behind app-lb** — `site/deploy.json` is an app-lb **static-site**
  deployment spec: app-lb serves `site/dist/` straight from the host (no VM,
  no image). Build, sync the files to the host at `site.root`, and apply:
  ```sh
  npm run build
  rsync -a --delete dist/ app-lb-host:/opt/fastcar-site/
  $EDITOR deploy.json        # set routes[0].host
  heyctl apply -f deploy.json
  ```
  The spec lists `/` as a public path (no sign-in gate). See the root
  [README](../README.md#marketing-site) for the full procedure.

## Design

The aesthetic mirrors the [Heyo Computer](https://heyo.computer) marketing
site: a dark terminal-frame layout (`#0a0c10`), a peach accent (`#e4a97d`),
IBM Plex Mono for body text, and Silkscreen for display headings. All design
tokens live as CSS custom properties at the top of `styles/site.css`.
