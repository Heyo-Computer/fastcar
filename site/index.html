a multi-vendor agent harness

Build agents that own their
threads & ship their work.

fastcar is built on the Pi coding-agent SDK. Give each agent a role, a model, a tool allowlist, and a set of MCP servers — and it owns its own threads. Schedule one on a cron and every morning's run lands in your inbox.

FEATURES

What's in the box

Everything you need to run a fleet of coding agents that talk to each other, to your tools, and to you.

⋈

Agents with their own threads

An agent is a role (its system prompt), a model and reasoning effort, a tool allowlist, and a subset of MCP servers — and it owns its own threads. Each thread is independently readable and linkable.

◷

Scheduled agents

Give an agent a schedule and it runs on a cron. Each firing creates a fresh thread — <schedule> — <date> — so every morning's run is its own thing. Missed firings fire once on restart, never overlapping.

▤

Inbox-first UI

The inbox is the landing page: one row per thread, newest reply first, with the agent, a preview, an unread dot, and chips linking to any artifacts the run published. Rows that need you are flagged.

→

Plan → approve → act

In planning mode the agent explores read-only, may ask clarifying questions, then submits a plan. Approve to execute; request changes to get a revision. Implementing tools stay blocked until you approve.

↳

Subagent delegation

maxcoding handles heavy coding; minimodel does fast exploration. They run in-process as Pi sessions with their own model and tools, with per-kind concurrency limits and an abort cascade.

⇄

Model routing

One shared Pi ModelRuntime serves every session. InceptionLabs Mercury for the conductor; everything else rides OpenRouter. Pick a model per agent, per subagent.

⚙

MCP servers

Extend agents with MCP servers — deployed endpoints (API key or OAuth) or code cloned and run locally over stdio. Each agent can be limited to a subset; plan mode allows only read-only tools.

⊞

Channels & artifacts

Agents publish HTML pages and markdown documents as artifacts on a canonical public path. Talk to them over Signal, email, or the inbox — channels your agents actually live on.

HOW IT WORKS

From task to shipped

Four steps, each visible in the UI as it happens.

01

Open the inbox

The app opens to your inbox. Threads that need you — a question to answer or a plan to approve — are flagged and filterable.

02

Give an agent a task

Pick an agent, drop a task (or a .md file, or a voice prompt). The conductor delegates by default: heavy work to maxcoding, exploration to minimodel.

03

Approve the plan

In plan mode the agent explores read-only and submits a plan, plus any questions only you can answer. Approve, and the thread flips to act mode.

04

It verifies & ships

The implementing subagent runs the project's tests/build/typecheck and reports a Verification section. Artifacts land on a public link in your inbox.

MODEL ROUTING

One runtime, many models

A single shared Pi ModelRuntime serves every session. The InceptionLabs provider is registered programmatically (OpenAI-compatible); everything else rides OpenRouter. Subagents are plain in-process Pi AgentSessions with their own model, tools, and system prompt.

  • Conductor: InceptionLabs Mercury
  • maxcoding → OpenRouter heavy coding model
  • minimodel → OpenRouter fast exploration model
  • Per-agent model & reasoning effort

MCP SERVERS

Extend every agent

Add MCP servers two ways: paste a deployed endpoint URL (with an API key in the headers, or OAuth discovered automatically), or hand it a GitHub URL and fastcar clones, builds, and runs it locally over stdio. Env vars, headers, and OAuth tokens are encrypted at rest. Each agent can be limited to a subset — enforced when a call is made as well as in its prompt.

  • Streamable HTTP with SSE fallback
  • OAuth dynamic registration + client metadata
  • mcp_list_tools & mcp_call
  • Plan mode allows only read-only tools
  agent  ──►  mcp_list_tools

    │             (API key / OAuth)
    ▼
  local clone  ──►  npm i && build
    │             stdio on demand
    ▼
  tools return to the agent turn
READY

Run a fleet of agents, not a chat box.

Clone fastcar, point it at Postgres, drop in your keys (or run it in mock mode with none) and you have the whole loop — agents, schedules, subagents, MCP, artifacts, and an inbox that opens first.

Get started on GitHub Read the features 
$ git clone https://github.com/Heyo-Computer/fastcar
$ cd fastcar && npm install
$ cp .env.example .env   # fill in keys (or set FASTCAR_MOCK=1)
$ npm run migrate && npm run dev
